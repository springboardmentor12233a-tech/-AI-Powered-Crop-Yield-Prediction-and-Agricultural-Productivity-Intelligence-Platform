## 3. Objective 2: Authentication and Data Collection Workflows

### How I got the datasets:
I sourced my agricultural data from Kaggle, a public data platform:
1. **Dataset A: Crop Recommendation Dataset** ([Kaggle Link](https://www.kaggle.com/datasets/arkabhowmik/crop-recommendation))
2. **Dataset B: Smart Crop Yield Prediction Dataset** ([Kaggle Link](https://www.kaggle.com/datasets/miadul/smart-crop-yield-predication-dataset))

### Why I chose these datasets:
- **Dataset A** is perfect for matching environmental conditions to crops. It tracks temperature, humidity, pH, and rainfall, and suggests which of **70 different crops** to grow.
- **Dataset B** helps me forecast the actual weight of the harvest. It tracks soil properties, weather, crop selection, and management details like fertilizer and pesticide usage, and outputs the yield in **tons per hectare**.
- Keeping them separate is critical because they do different things (classification vs. regression) and do not share any matching IDs (like farm plot IDs) to join them.

### Setting up Authentication:
I implemented API routes in `src/api/routers/auth.py` using FastAPI. 
- *Why I did this*: I need different access levels. A **Farmer** should only see their own crop records, an **Agronomist** should see regional analysis, and an **Admin** manages the system.
- *How I did this*: I created a mock JWT authentication endpoint. When a user logs in with valid credentials, the API returns a Base64-encoded token containing their name and role claim. Future routers decode this token to restrict access.

## 4. Objective 3: Dataset Preprocessing and Management System

This objective covers three main areas: data cleaning (preprocessing), validation checks, and visual exploration (EDA).

### A. Preprocessing (Data Cleaning)
I wrote `src/data/smart_crop_yield_preprocessing.py` to fix quality issues:
1. **Empty Cells (Missing values)**: The raw yield dataset had missing entries in `Irrigation` (25.38% blank) and `Previous_Crop` (20.31% blank). Instead of guessing category names (like assuming missing irrigation means "Rainfed"), I mapped all blank cells to `"Unknown"` to avoid biasing my models.
2. **String Trimming**: Raw text categories had trailing spaces (e.g. `'Rice '` and `'Rice'`). I trimmed all string columns (`str.strip()`) to ensure categories match properly.

### B. Range Validation Checks
In `src/data/validation.py`, I implemented code to check data limits:
1. **Hard Rules**: If a value is impossible (e.g., pH above 14 or negative rainfall), the script stops and raises a `ValidationError`.
2. **Soft Warnings**: If a value is extreme but physically possible (e.g., monsoon rainfall of 5,990 mm, which is realistic for tropical crops like jute), the script prints a log warning but keeps the row intact so I don't lose valid data.

### C. Exploratory Data Analysis (EDA)
I wrote the script `notebooks/eda.py` to inspect the datasets visually.

#### Why I chose specific EDA charts:
1. **Class Distribution (Dataset A)**: I plotted a bar chart of the `Label` column to ensure that I have a balanced dataset (I found exactly 100 samples per crop, confirming perfect class balance).
2. **Yield Histogram (Dataset B)**: I plotted the yield column to see its shape. It shows a normal bell-curve, which is great for regression models.
3. **Correlation Heatmap (Dataset B)**: I plotted correlations to see how columns relate to yield. I discovered that weather features had near-zero correlation to yield, while fertilizer and pesticide usage had high correlations. This confirms the dataset is simulated/synthetic.

#### EDA Code Walkthrough:
Here is the code I wrote to perform the EDA and save plots:

```python
# notebooks/eda.py
import os
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

def generate_eda():
    # Setup folders to save plots
    os.makedirs("artifacts/eda", exist_ok=True)
    
    # Load processed datasets
    df_a = pd.read_csv("data/processed/crop_recommendation_cleaned.csv")
    df_b = pd.read_csv("data/processed/smart_crop_yield_cleaned.csv")
    
    # ----------------------------------------------------
    # Plot 1: Target Balance for Dataset A
    # Chosen to confirm that we have enough samples for each of the 70 crops.
    # ----------------------------------------------------
    plt.figure(figsize=(15, 6))
    sns.countplot(data=df_a, x='Label', order=df_a['Label'].value_counts().index)
    plt.xticks(rotation=90, fontsize=6)
    plt.title("Dataset A: Samples per Crop Type (Balanced Check)")
    plt.tight_layout()
    plt.savefig("artifacts/eda/dataset_a_class_balance.png")
    plt.close()
    
    # ----------------------------------------------------
    # Plot 2: Yield Target Distribution for Dataset B
    # Chosen to understand the distribution shape of my prediction target.
    # ----------------------------------------------------
    plt.figure(figsize=(8, 5))
    sns.histplot(df_b['Yield_ton_per_ha'], kde=True, color='blue')
    plt.title("Dataset B: Distribution of Yield (Tons per Hectare)")
    plt.savefig("artifacts/eda/dataset_b_yield_distribution.png")
    plt.close()
    
    # ----------------------------------------------------
    # Plot 3: Numerical Correlation Heatmap for Dataset B
    # Chosen to verify which features have direct relationships with yield
    # and to detect potential data leakage issues.
    # ----------------------------------------------------
    plt.figure(figsize=(10, 8))
    numeric_cols = df_b.select_dtypes(include=['float64', 'int64'])
    corr = numeric_cols.corr()
    sns.heatmap(corr, annot=True, cmap='coolwarm', fmt=".2f", linewidths=0.5)
    plt.title("Dataset B: Feature Correlation Matrix")
    plt.tight_layout()
    plt.savefig("artifacts/eda/dataset_b_correlation_heatmap.png")
    plt.close()
    
    print("EDA Visualizations created successfully under artifacts/eda/")

if __name__ == "__main__":
    generate_eda()
```

## 5. Objective 4: System Design and UI Planning

### Database Design:
I designed a database model in `docs/database_schema.md` using PostgreSQL:
- **Why PostgreSQL**: It is a relational database. I have connected items: a `User` owns a `Farm`, which has `Plots`, which record `Soil_Observations` and `Predictions`. Relational tables keep these linked.
- **Table Design**: I created SQL schemas with indexes to make searches fast, and set enums (restricted dropdown lists) for columns like `irrigation_type` to prevent typos.
- **MongoDB**: I planned MongoDB collections strictly as a future design component to store unstructured telemetry streams from active IoT soil sensors.

### UI Planning:
I wrote `docs/ui_layout.md` to map out what the screens will look like:
- **Farmer Dashboard**: Displays cards for active weather parameters, an input form to request a crop recommendation, and widgets to forecast yield.
- **Agronomist Portal**: Provides maps showing farm plots and regional analysis exports.
- **Aesthetic Guidelines**: Specified modern Outfit and Inter fonts, glassmorphism cards with blurred backdrops, and emerald-green color accents.
