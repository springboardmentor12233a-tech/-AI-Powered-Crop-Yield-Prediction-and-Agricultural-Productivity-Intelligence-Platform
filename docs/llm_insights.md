# LLM-Based Agricultural Insights Layer

## Purpose
The LLM Insights layer adds a natural language interpretation capability on top of the raw, structured Agricultural Forecast Report. It serves as an analytical AI assistant that translates quantitative statistical associations (e.g., yields, quartiles, correlations) into concise, human-readable insights.

Crucially, **the LLM interprets the structured analytical output and does not replace the ML prediction or statistical analysis.** It relies entirely on the deterministic backend workflow to provide the ground-truth data.

## Input & Output
- **Input:** A highly structured JSON report generated by the `generate_agricultural_report` function (which includes Yield Prediction, Weather Context, and Soil Context).
- **Output:** A strict JSON object structured to seamlessly integrate with frontend consumption.
  
### Output Structure
```json
{
    "summary": "Cautious summary of prediction and context.",
    "yield_interpretation": "Statement about the predicted yield.",
    "weather_insights": ["Insight 1", "Insight 2..."],
    "soil_insights": ["Insight 1", "Insight 2..."],
    "attention_points": ["Notable below average/negative correlations..."],
    "limitations": ["Reminder that these are associations, not causation."]
}
```

## Prompt Constraints and Hallucination Controls
To ensure the LLM strictly serves as an interpreter and avoids inventing facts, the system prompt employs strong constraints:
- **Grounding**: The LLM is restricted to *only* use facts and numbers present in the input JSON. It cannot reference external knowledge regarding crop requirements.
- **Cautious Terminology**: The LLM is instructed to use phrases like "historically associated with" and "the model predicts."
- **Prohibited Words**: Words establishing direct causation ("causes", "guarantees") or biological optima ("ideal", "best soil", "increase X to increase yield") are explicitly forbidden.

## Error Handling & Configuration
The API gracefully falls back if the Groq LLM provider is unavailable:
- **Missing API Key:** Triggers a clean HTTP 503 Service Unavailable indicating configuration is needed.
- **Timeouts/Connection Failures:** Returns HTTP 502 Bad Gateway.
- **Parsing Errors:** Returns HTTP 502 if the LLM output is not valid JSON.

### Configuration Variables
Set these variables in your environment (or `.env` file for local development):
- `GROQ_API_KEY`: Your Groq API key (Required).
- `GROQ_MODEL`: Target model (Optional, defaults to `openai/gpt-oss-20b`).
- `GROQ_BASE_URL`: API Base URL for Groq API (Optional, defaults to `https://api.groq.com/openai/v1`).

## Limitations
- The LLM's interpretation is only as accurate as the underlying historical training dataset. It does not establish causal or agronomic rules.
- Because it uses zero-temperature generation for consistency, it lacks creative diversity but maximizes deterministic reliability.
